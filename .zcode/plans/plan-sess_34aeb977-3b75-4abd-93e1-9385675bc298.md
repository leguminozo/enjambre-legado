## Fix: `useSidebarBadges` Supabase Realtime errors (expired JWT + heartbeat timeout)

Surgical change to **one file**: `apps/nucleo/src/hooks/useSidebarBadges.ts`. No other files touched. No new helper, no context provider, no schema/auth-package changes.

### Root cause
The realtime effect (lines 200–227) subscribes a channel once at mount and only `console.error`s on errors. It never tears down + re-subscribes when:
- The access JWT expires mid-session → server replies `InvalidJWTToken: Token has expired` → `CHANNEL_ERROR`.
- The websocket heartbeat dies → `TIMED_OUT` / `CLOSED`.

The `@supabase/ssr` browser client auto-refreshes the token on its shared socket, but the channel subscription is not re-bound after the rejection, so the errors recur (1153s, 1157s as seen in the logs). Also, every `postgres_changes` event in any of the 3 tables fires `fetchBadges()` with no debounce → write bursts thrash the RPC + `auth.getUser()`.

### Changes to `useSidebarBadges.ts`

**1. Debounced `fetchBadges` for realtime events (reduce thrash)**
- Add a `fetchBadgesDebounced` (trailing ~300 ms) built from `fetchBadges` via a `useRef` timer. The mount/initial fetch (Effect #1, idle-deferred) still calls `fetchBadges()` directly and immediately. Only the realtime event handlers use the debounced version.
- Nota del usuario: este patrón queda instalado para futuras escuchas (e.g. `alertas_fitosanitarias` si se añaden luego para el rol `territorial`).

**2. Rewrite the realtime effect (Effect #2) — three additions:**

- **Session-gated subscribe:** `await supabase.auth.getSession()` before creating the channel. If there is no active session, do not subscribe yet (RLS would silently drop payloads anyway); rely on the `onAuthStateChange` listener (next bullet) to subscribe once a session appears.

- **`onAuthStateChange` re-subscribe:** register `supabase.auth.onAuthStateChange((event) => { ... })`. On `SIGNED_IN`, `TOKEN_REFRESHED` → tear down the current channel (if any) and (re)create it with the fresh session. On `SIGNED_OUT` → tear down the channel only. Store the `{ data: { subscription } }` in a ref and unsubscribe in the effect cleanup.
- Especialmente relevante ahora: el admin crea cuentas directas desde el Panel de Identidades (`POST /api/admin/crear-cuenta`); sesiones largas donde el token expira en mitad de la operación. Sin este fix el sidebar quedaría sordo.

- **Reconnect-with-backoff on terminal/transient statuses:** in the `.subscribe((status, err) => …)` callback:
  - `SUBSCRIBED` → reset backoff attempt counter to 0.
  - `TIMED_OUT` | `CLOSED` | `CHANNEL_ERROR` → `console.error('[useSidebarBadges] realtime error', status, err)` (preserve existing log prefix), then `supabase.removeChannel(channel)` and schedule a re-subscribe via exponential backoff (base 1 s, ×2, capped at 30 s, ~5 attempts max), each new attempt resolving a fresh `getSession()` first.

- **Cleanup:** effect's return now clears the backoff timer, removes any active channel, and unsubscribes the `onAuthStateChange` subscription.

- **Channel name:** keep the random `sidebar-badges-${Math.random()…}` convention (Strict Mode / "cannot add postgres_changes callbacks after subscribe()" comment preserved). No change to naming.

### What stays unchanged
- `fetchBadges` / `fetchBadgesLegacy` / `mapRpcToBadges` / cache logic / `DEFAULT_BADGES` / `safeCount` (Effect #1 and the fetch body untouched).
- Hook return signature: `{ badges, isLoading, refetch: fetchBadges }` — no API change for the 3 consumers (Sidebar, SidebarRail, MobileNavSheet).
- The shared `@enjambre/auth` browser singleton client (`apps/nucleo/src/lib/supabase.ts`) — no changes to the client, no access-token injection, no `realtime: { params: { access_token } }`.
- No `any` (use `unknown` + guards where needed), named exports only, comments only where explaining "why".

### Out of scope (deliberately, per user)
- No se añade `alertas_fitosanitarias` a las escuchas ahora. El rol `territorial` no escribe en `varroa_records`/`logistica_envios`/`facturas_emitidas` (Capa C, RLS), así que el canal queda inactivo para ese usuario — silencio, no error. Queda como mejora futura si se quiere que el badge `territorio` parpadee ante alertas fitosanitarias cercanas.
