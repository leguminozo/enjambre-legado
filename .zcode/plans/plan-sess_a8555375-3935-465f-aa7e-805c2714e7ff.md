# Movimiento 6 — Trazabilidad real y honesta

## Diagnóstico (verificado)
- El anclaje on-chain existe (viem + Polygon Amoy, contrato `anchor(bytes32)`, `provider.ts`) pero **está roto**: `anchors.ts:126` inserta la columna `timestamp` (no existe; es `block_timestamp` según migración 54) y ordena GET por `timestamp` (`anchors.ts:212`) → el POST /anchor siempre falla en persistencia. Además `entity_type` CHECK solo admite `('lote','colmena','inspeccion')` y el módulo intenta insertar `cosecha`/`apiario`.
- El hash de lote de `add_traceable_stock` es `sha256(producto+now+uuid)` — sin payload, no verificable.
- La página pública `/producto/[slug]/trazabilidad` dice "Integridad Certificada en Postgres" y **no verifica nada** en cadena.
- El QR por frasco YA existe (PDP → página de trazabilidad); falta que la página verifique de verdad.

## Cambios

### 1. Migración `20260802_real_traceability.sql` (packages/database)
- `ALTER TABLE blockchain_anchors ADD COLUMN data_payload JSONB;` (payload EXACTO firmado, para que la página pública lo muestre y se pueda re-hashear)
- Ampliar CHECK de `entity_type` a `('lote','colmena','cosecha','apiario','inspeccion')`
- Índice `(entity_type, entity_id)`
- `pnpm db:typegen`

### 2. nucleo `api/routes/blockchain/anchors.ts` (fix + enriquecimiento)
- `timestamp` → `block_timestamp` en el insert; GET ordena por `block_timestamp`
- Payload real del lote al anclar: nombre_lote, variedad, kg_total, estado, análisis lab (humedad/HMF si existen), relato, fecha_envasado, cosecha_ids, nombres de colmenas y apiario — el mismo payload que mostrará la página pública
- Guardar `data_payload` en el anchor (el `computeDataHash` ya es determinista: `{entityType, entityId, data}` → la página puede recomputar y comparar)
- `cosecha`/`apiario` funcionan tras ampliar el CHECK

### 3. nucleo `routes/produccion.ts /add-stock` (anclaje por defecto, fail-open)
- Tras crear el lote vía RPC: construir payload real {producto, cantidad, kg, lote_id, hash_identificador, fecha} → `provider.anchor(computeDataHash('lote', id, payload))`:
  - Éxito → `lotes.blockchain_hash = txHash` + registro en `blockchain_anchors` con `data_payload` → devolver txHash (el toast de "Relleno Rápido" ya muestra el hash)
  - Sin `BLOCKCHAIN_ANCHOR_PRIVATE_KEY` o tx fallida → NO bloquear la reposición de stock: queda el hash local y la página lo etiqueta honestamente como "sin ancla on-chain" (try/catch + log)
- El endpoint admin `/anchor` queda para re-firmar lotes cuando lleguen datos de laboratorio (nueva versión de ancla; la página muestra la más reciente)

### 4. tienda página `/producto/[slug]/trazabilidad` (verificación real)
- Con `product.lote_id` (ya disponible en `PRODUCT_SELECT`), consultar `blockchain_anchors` (RLS SELECT es pública) → último anchor del lote
- Si es on-chain: mostrar el **payload exacto firmado** (`data_payload`), el `data_hash`, y **verificación en vivo** vía `POST /api/blockchain/verify` (ya es público por `publicPaths`) → "Verificado en Polygon Amoy · bloque N" + link explorer (con try/catch: si nucleo cae, muestra datos del anchor sin check en vivo)
- Si solo hay hash local: badge honesto "Firma local — pendiente de anclaje en cadena" (reemplaza "Integridad Certificada en Postgres")
- Textos actualizados según estado real; el QR del PDP no cambia

### Nota de ops
- Requiere `BLOCKCHAIN_ANCHOR_PRIVATE_KEY` + `BLOCKCHAIN_ANCHOR_CONTRACT_POLYGON_AMOY` en nucleo. Amoy es testnet (gratis); mainnet queda configurable por env sin cambio de código (documentado en el plan, no se fuerza).
