# Movimiento 2 — CAF automático (solicitud de folios al SII)

## Diagnóstico (verificado)
- **No existe** ningún código de solicitud de folios (sin `SolicitudDeFolios`, `GetCAF`, `CrSeed` en código).
- Todo el andamiaje base ya está: token SII por clave tributaria (`sii-client.ts getSiiToken`, cookie 1h), firma xmldsig con P12 (`signDteXml`), **`parseCafXml` ya parsea el XML AUTORIZACION/CAF de respuesta** (TD/D/H/FA/FRMA/RSASK/RSAPUBK — lo que usa la importación manual), guard fail-closed (`SII_CAF_MIN_FOLIOS`=10), alerta (`SII_CAF_ALERT_THRESHOLD`=50 → `notifyCafLowFolios`), cola `sii_document_jobs`.

## Diseño

### 1. `packages/contable` — builder + firma de la solicitud (con tests)
- `buildSolicitudFoliosXml({ rutSolicitante, rutEmpresa, tipoDte, cantidad })` → XML canónico `SolicitudDeFolios` (namespace SII, `TipoSolicitud=0`).
- `signSolicitudFolios(xml, p12, password)` → firma xmldsig RSA-SHA1 inline sobre el elemento raíz (reutiliza el patrón de `signDteXml`; si el helper se puede generalizar, se refactoriza mínimamente sin cambiar su contrato).

### 2. `apps/nucleo/src/api/lib/sii-caf-client.ts` (nuevo) — cliente de solicitud
- `requestCaf({ admin, empresa, tipoDte, cantidad })`:
  1. `resolveSiiCredentials` (P12 activo + clave desencriptada — ya existe)
  2. `getSiiToken(rut, dv, siiClave)` (ya existe) → cookie `token=...`
  3. `POST {SII_ENV}/cgi_dte/U.Certifica/GetCaf` con body XML firmado + cookie
  4. Respuesta → `parseCafXml` → CAF tipado
- Timeout + error tipado + log.
- ⚠️ **Nota de ops**: el endpoint/params exactos del SII para GetCaf tienen variantes según el servicio (WS con seed/token vs. portal con clave tributaria). Se implementa con el patrón del repo (token por clave tributaria) y queda **configurable por env** (`SII_CAF_URL_OVERRIDE`); la validación final requiere probar contra `maullin.sii.cl` (certificación) con credenciales reales — el código se testea con fixtures.

### 3. Tabla `sii_caf_requests` (migración nueva) — idempotencia/auditoría
- `id, empresa_id, tipo_dte, cantidad, estado ('pending'|'success'|'failed'), error text, caf_id uuid, requested_at, completed_at` — RLS service_role (como `sii_caf`).
- Unique parcial: una `pending` por (empresa, tipo_dte) → evita solicitudes en paralelo.

### 4. `caf-auto-worker.ts` (nuevo) — orquestación
- `ensureCafFolios(admin, empresaId, tipoDte)`: si folios restantes < umbral `SII_CAF_REQUEST_THRESHOLD` (default 30) **y** no hay request pending → crea `pending` → `requestCaf` → inserta el CAF con la misma lógica del import manual (desactiva otros del mismo tipo, `folio_actual = desde-1`) → `success` + `caf_id`. Fallo → `failed` con error (la alerta manual sigue cubriendo).
- Kill-switch: **`SII_CAF_AUTO_ENABLED` (default `false`, opt-in)** — requiere credenciales probadas contra el SII.
- Hook en `caf-alert-worker.ts`: cuando la alerta se dispara y auto está enabled → intenta solicitar ANTES de notificar (o además).

### 5. Rutas admin (sii/caf.ts)
- `POST /api/sii/caf/auto-request` (admin/gerente): disparo manual con `{ tipo_dte, cantidad? }`.
- `GET /api/sii/caf/requests`: historial de solicitudes (estado, error, folios).

### 6. Env + docs
- `SII_CAF_AUTO_ENABLED`, `SII_CAF_REQUEST_QTY` (default 100), `SII_CAF_REQUEST_THRESHOLD` (default 30), `SII_CAF_URL_OVERRIDE` → agregar a `docs/ENV-CHECKLIST.md` y `.env.example`.

### 7. Tests
- `packages/contable`: builder XML (estructura canónica, cantidades/tipos), firma agrega `<Signature>`.
- `sii-caf-client.test.ts` (fetch mockeado): requestCaf → parsea CAF real del fixture XML; respuesta inválida → error tipado.
- `caf-auto-worker.test.ts` (supabase mock con filtros): umbral bajo → solicita e inserta; pending existente → no duplica; fallo → failed + alerta intacta.
- Ruta admin meso (patrón checkout-integrity).
